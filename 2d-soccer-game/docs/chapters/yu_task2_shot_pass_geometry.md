## 2. B-Y2 射门线路的几何定义（`shot_open`）

### 2.1 规则

球路被看成一个半径为 `ballR` 的圆沿直线移动。机器人是半径 `robotR` 的圆盘。从球心出发、沿球路走了 s 米的位置，走廊半宽为：

```
w(s) = robotR + ballR + margin + s · tan(k · kickNoise)
     = 0.15   + 0.07  + 0.02   + s · tan(6°)        （默认 k = 1）
```

- 机器人中心到球路的距离小于 w(s) 时，算挡住。余量 slack = 距离 − w(s)，slack ≥ 0 表示畅通。
- 走廊随距离变宽，用来覆盖踢球方向误差：k = 1 表示覆盖 1 个标准差。
- 球后方的机器人（投影 t ≤ 0）忽略，因为球在离开它们。
- 踢球者本人不算障碍。
- 图：`fig2_shot_corridor.png`。

在 x = ±(L/2 + ballR) = ±4.57 的线上取 9 个瞄准点。这条线就是裁判判定进球的位置；取在 4.5 会让斜射偏差 0.07 m。瞄准点 T 可用，需要同时满足：

1. 球到 T 的走廊里没有机器人（门将也算障碍）。
2. 噪声锥到达门线时仍在门柱以内：\|T_y\| + d · tan(k · σ) ≤ 1.23（CourseSimplified）。

此外还要满足射程条件：1.8 m/s 的射门到门线时速度 ≥ 0.5 m/s，即 d ≤ 3.74 m。`S.open = 存在可用瞄准点 且 在射程内`。

### 2.2 接口（供 Fayne 的 B-F2/B-F3 使用）

```matlab
Q = tdp.shotLaneParams(P);                                   % 阈值
S = tdp.shotOpen(ball, team, pos, valid, kicker, P, Q);
% S.open          shot_open 标志
% S.target        最佳瞄准点（余量最大；余量相同时取离球门中心最近的）
% S.slack, S.openFraction, S.inRange, S.arrivalSpeed
% S.reason        0 可射 | 1 超出射程 | 2 门将挡（去掉门将就有线路）
%                 3 对方场上球员挡 | 4 队友挡 | 5 角度太小（噪声锥出了门柱）
% S.keeperOut     对方门将离开球门区 +0.10 m —— 与线路是否畅通分开报告
% S.openWithoutKeeper, S.keeperKnown, S.targetsY, S.targetSlack
P2 = tdp.passOpen(ball, team, pos, valid, kicker, receiver, P, Q);
% P2.open / slack / blocker / speed（沿用旧版 actionSelection 的 sqrt(2ad)+0.2）
% P2.pressured    接球人 0.28 m 内有对手（只报告，不计入 open）
```

`pos` 是 8 × 2 的机器人位置。`valid` 为假的机器人被忽略，函数本身不猜测位置。函数纯几何、无状态、不读写战术记忆，红蓝严格镜像（200 个随机世界验证）。选哪个队友接球、什么时候射门，属于 Fayne 的 B-F2 决策规则，本函数不做。

**"线路畅通"与"门将离线"是两个独立输出：**
- S2：门将离线，线路畅通。
- S7：门将离线，但被后卫挡住 → `keeperOut = true`、`open = false`、`reason = 3`。
- S1：门将在线，但球门远角仍有线路 → `open = true`、`keeperOut = false`。

## 3. B-Y3 射门/传球测试场景与验证

### 3.1 十个受控场景（预测 vs 仿真）

- **场景设置：** 每个场景冻结一个世界：蓝队进攻 +x，1、5 号为门将，对方门将按 V1 规则站位（x = 4.15，y = 0.5 × 球的 y）。
- **观测值：** 用比赛自带的 `tdp.ballModel` + `tdp.collisions`，让球滚过静止机器人。
  - 名义射门：无方向误差，射向判定的最佳瞄准点。
  - 1000 脚带比赛噪声（σ = 6°）的射门，统计"不碰任何机器人而进球"的比例 pMC。
- **"观测为开放"的标准：** 名义射门成功，且 pMC ≥ 0.80。1σ 走廊在余量为 0 时的设计成功率约 84%，所以 0.80 是与之匹配的阈值。
- **复现与图：** `yuShotScenarios(1000, 7)`；图 `fig3_scenarios.png`。

| 场景 | 预期 | 预测 | 原因码 | 余量 (m) | 名义 | pMC | 一致 |
|---|---|---|---|---|---|---|---|
| S1 球门无遮挡，门将在线 | 开放 | 开放 | 0 | +0.17 | ✓ | 0.93 | ✓ |
| S2 门将离开球门 | 开放 | 开放，keeperOut | 0 | +0.96 | ✓ | 1.00 | ✓ |
| S3 场上球员挡在球前 0.6 m | 被挡 | 被挡 | 3 | −0.10 | ✗ | 0.23 | ✓ |
| S4 小角度，门将封近门柱 | 被挡 | 被挡 | 2 | −0.08 | ✓ | 0.60 | ✓ |
| S5a 阈值：挡球者在走廊外 3 cm | 刚好开放 | 开放 | 0 | +0.03 | ✓ | 0.88 | ✓ |
| S5b 阈值：挡球者在走廊内 3 cm | 刚好被挡 | 被挡 | 3 | −0.03 | ✓ | 0.77 | ✓ |

\* 传球的 pMC 是"除接球人外没有机器人先碰到球"的比例，即线路是否畅通。**真正传到接球人脚下的只有 61%**（S8，2.3 m）：6° 误差在 2.3 m 外偏出约 0.25 m，比接球半径 0.22 m 还大。这是踢球精度问题，不是线路问题，但会直接影响 Fayne 的传球优先策略。建议 B-F2 把传球距离限制在约 2 m 内，或者把"传到接球人附近"也算作成功。

**10/10 一致。** S4 和 S5b 很能说明问题：名义射门能进，但带噪声时成功率只有 0.60 和 0.77。判定为"被挡"是正确的保守结论。

### 3.2 阈值标定

一个静止的挡球者放在 3 m 射门路径上的 0.6、1.2 或 2.0 m 处，横向从 0 移到 0.8 m，每个位置踢 400 脚（`yuShotThreshold`，图 `fig4_threshold.png`）。把"slack ≥ 0"与"成功率 ≥ 0.80"对比，结果如下：

| 走廊宽度 k | 一致率 | 判"开放"但其实不可靠 | 判"被挡"但其实可靠 |
|---|---|---|---|
| 0（不考虑噪声） | 87.0% | 16 | 0 |
| 0.5 | 96.7% | 4 | 0 |
| **1（默认）** | **95.1%** | **0** | **6** |
| 1.5 | 87.8% | 0 | 15 |
| 2 | 78.9% | 0 | 26 |

**选 k = 1：** 它从不把不可靠的射门判成"开放"，代价是 6 个边缘位置被保守地判为"被挡"。挡球者越远，成功率曲线越平缓，单一的 k 无法让所有距离都完全一致。

### 3.3 真实比赛回放检验（机器人在移动）

30 场 V1.2 比赛（中立/中立、进攻/防守、防守/进攻各 10 个种子 × 300 s），检测到 227 次射门（踢球速度 ≥ 1.75 m/s、朝向进攻方向）。每次射门都用射门**前一拍**的局面计算判定，再按记录追踪球的去向：自由滚动按 `ballModel` 逐拍核对，误差 1e-9 m。结果文件：`build/yu-task2/shot_replay.csv`；图：`fig5_replay_shots.png`。

| 发现 | 数字 |
|---|---|
| 射门总数 / 不碰任何人直接进球 | 227 / **5（2.2%）** |
| 现有协调器**总是瞄准球门正中** | 正中线路 **100% 被挡**：门将 160 次（70%），对方场上球员 67 次（30%） |
| 射门后 0.1 s 内就被对手碰到（射门时对手已贴身） | 103 次（45%） |
| 射门那一刻存在其他开放瞄准点（`S.open`） | 32 次（14%），这些情况换个方向射本可以更好 |
| **沿实际踢出方向**的线路检验 vs 结果 | 判定开放 4 次 → 进 3 个；判定被挡 223 次 → 进 2 个（余量只差 2–3 cm，挡球者在球滚动期间移开） |

**结论：**
- 这个几何判定在机器人移动的真实比赛中也有很强的区分度：线路开放时进球率 75%，被挡时 0.9%。
- 对 Fayne 的直接建议：Test 2 的"红队能射就射"应该**射向 `S.target`，而不是球门正中**；否则，现有的每一次射门在出脚时线路就已经被门将或后卫封住，只增加射门次数不太可能多进球。
- 30 场比赛共进 35 球，只有 5 个来自干净的射门，其余 30 个来自速度低于 1.75 m/s 的踢球（带球），或球被碰过之后入网，本次没有再细分。**因此"射门次数多"不等于"进球多"，Qin 的统计里应区分这两类。**
