## 1. Y1 核对记录：现有球场与球

### 1.1 坐标系

- 原点在中点 (0, 0)，x 沿球场长边，y 沿宽边，单位米。
- **蓝队（1–4 号）进攻 +x、防守 −x；红队（5–8 号）进攻 −x、防守 +x**（`P.dirSign = [1 -1]`）。
- 开球时：所有蓝队机器人 x < 0、红队 x > 0，红队位置是蓝队关于原点的点对称；蓝队朝向 0（面向 +x），红队朝向 π；所有人都在中圈外。（测试 `testKickoffOwnHalvesFacingAndMirror`）

### 1.2 关键位置（与课程表 1、`docs/球场与球建模参数核对表.docx` 一致）

| 项目 | 数值（m） | 代码字段 |
|---|---|---|
| 比赛区 | 9 × 6，底线 x = ±4.5，边线 y = ±3.0 | `L`, `W` |
| 球门 | 开口 y = ±1.3，深 0.6（向场外） | `goalW`, `goalD` |
| 球门区 | 前沿 x = ±3.5，侧沿 y = ±1.5 | `goalAreaL`, `goalAreaW` |
| 罚球区 | 前沿 x = ±2.5，侧沿 y = ±2.5 | `penAreaL`, `penAreaW` |
| 缓冲带外沿 | x = ±5.5，y = ±4.0 | `border` |
| 球半径 | 0.07 | `ballR` |

### 1.3 球的运动（测试验证过的数字）

| 情况 | 结果 |

|---|---|---|

| 边线出界 | \|y\| > 3.07 → 放到 y = ±2.75；\|y\| = 3.06 仍在场内 | 同上 |

### 1.5 发现的问题与简化（不影响当前比赛运行，供小组决定）

1. **二维没有门柱和球网。** 球在 1.23 < \|y\| < 1.37 越过底线时判出界；在 Webots 里这个范围会打到门柱（柱心 y = ±1.35，宽 0.10）。
2. **机器人可以走进球门里面。** 机器人只受外缓冲带限制（\|x\| ≤ 5.35），可以站在底线后面、球门内部（测试 `testRobotCanStandInsideGoal` 记录了这一现状）。Webots 里 x = ±5.10 有球网。
3. **外缓冲带反弹在正常比赛中用不到。** 最快的球每步最多走 2.2 × 0.05 = 0.11 m，裁判在 4.57 / 3.07 就会停止比赛，球不可能到达 5.43 / 3.93。所以 `ballRestit = 0.5` 实际上不起作用（`testBorderBounceUnreachableInPlay`）。
4. **两种裁判配置的门柱规则不同。** ACompat 是 \|y\| < 1.30，CourseSimplified 是 \|y\| + 0.07 < 1.30。统计时必须和比赛用同一种配置；`tdp.ballHalf` 已按 `P.rulesProfile` 自动选择（`testACompatPostRuleDiffers`）。
5. **边线球在无人触球时的归属。** `Referee2D.m` 第 27 行 `owner = 3 - lastTouch`，开场无人触球时 `lastTouch = 0`，会得到不存在的 3 号队。CourseSimplified 下 owner 不被使用，所以没有实际影响；ReferenceRestarts 第 36 行另有保护。建议由负责裁判代码的同学确认，本次未修改。

## 2. 空间分区（F4 第 4 节）

### 2.1 区域表

所有区域都写在**球队坐标系**里，与 V1.2 的阈值约定一致：`f = dirSign × x`，`lat = dirSign × y`。f = −4.5 是本方门线，0 是中线，+4.5 是对方门线。红队是蓝队关于原点的点镜像，所以两队共用一张表。

| id | 名称 | 区域（f 范围 × lat 范围） | 来源标线 |
|---|---|---|---|
| 1 | OwnGoalArea | [−4.5, −3.5] × \|lat\| ≤ 1.5 | 球门区 |
| 2 | OwnPenaltyArea | [−4.5, −2.5] × \|lat\| ≤ 2.5，扣除 1 号区 | 罚球区 |
| 3 | OwnThird | [−4.5, −1.5] 全宽，扣除 1、2 号区 | 三分之一线（L/3） |
| 4 | OwnMiddle | (−1.5, 0] 全宽 | 中线 |
| 5 | OppMiddle | (0, 1.5] 全宽 | |
| 6 | OppThird | (1.5, 4.5] 全宽，扣除 7、8 号区 | |
| 7 | OppPenaltyArea | [2.5, 4.5] × \|lat\| ≤ 2.5，扣除 8 号区 | |
| 8 | OppGoalArea | [3.5, 4.5] × \|lat\| ≤ 1.5 | |
| 0 | OffPitch | 球整体出界，或坐标无效 | 与裁判一致 |

编号从本方球门向对方球门递增，所以"球在 1–3 号区"就等于原来的 `forward ≤ −1.5`。Fayne 只需要把纵深比较换成区域编号判断：

```matlab
[zone, ~] = tdp.spatialZone(ball(1), ball(2), team, P, prevZone);   % prevZone 每拍传回
mustContest = zone >= 1 && zone <= 3;   % 替代 forward <= v12ContestDepth (Neutral)
```

**压线归属：** 画了线的区域（球门区、罚球区）拥有自己的边线，符合足球规则；没画线的三分之一线和中线，归离本方球门更近的区域（`testTiesOnLines`）。

### 2.2 进出区滞回（回答问题 3）

**结论：要分开设置进区和出区条件，并且与 `v12SwitchMargin` 分开。** `v12SwitchMargin` 管的是"换谁去抢"，区域滞回管的是"球算在哪个区"，两者不应共用同一个数。

规则：只要点离上一拍所在区域不超过 `P.zoneHysteresis`（默认 0.20 m），就保持原区域。因此跨线时要越过 0.20 m 才算进入新区，退回时也要越过 0.20 m 才算回到原区。效果是以标线为中心、总宽 0.40 m 的滞回带。

| 球的 f（原区 4 → 往本方门走） | −1.49 | −1.69 | **−1.71** | 往回 −1.31 | **−1.29** |
|---|---|---|---|---|---|
| 区域 | 4 | 4 | **3** | 3 | **4** |

0.20 m 的取值依据：
- 是现有测试中 ±2 cm 抖动的 10 倍。
- 大于最快球速每步的位移（2.2 × 0.05 = 0.11 m），所以一步不会跳过整个滞回带。
- 约等于机器人半径与球半径之和（0.22 m）。

嵌套区域（例如从三分之一区进入罚球区）同样适用，无论是从前沿还是侧沿进入（`testEnterAndExitThresholds`）。球在任意标线上 ±2 cm 来回 200 次，区域都不会改变（`testJitterOnLineDoesNotFlip`）。

### 2.3 边带与出界（回答 6.4）

- **球：** 球心越过线不超过 `ballR`（只是部分出界）时仍算场内，并被归到最近的区域；整球越过门线或边线时为 0 号区，即使有上一拍的区域也不保留。这样球停在边带里、裁判还没重新开球时，也不会被算进某个区域（`testBallOverLinesAndBorderStrip`）。
- **机器人：** 调用时取 `margin = Inf`，机器人在 1 m 边带里或球门后面时，被归到最近的场内区域。
- **结论：分区只覆盖比赛区，不覆盖边带。**

### 2.4 球心还是整个球（回答 6.2）

**区域归属按球心判断**，与现有战术代码一致，也与镜像测试兼容。只有"出界、进球"这两类按整球判断，因为必须和 `Referee2D` 的判罚一致。

## 3. 半场判定（Y3 / F4 6.1）

### 3.1 决定：统计用 x = 0 硬边界（待 Qin 确认）

| 方案 | 采用？ | 理由 |
|---|---|---|
| x = 0 硬边界，按球心 | **是**（`ballHalf` 默认） | 这是球场标线；红蓝对称；与战术参数无关，调战术不会改变统计口径 |
| ±0.15 m 带（`v1MidlineBand`） | 否，只作诊断 | 这是协调器切换攻防用的控制滞回，不是场地标线；用它切分时间会把战术参数混进统计 |

`tdp.ballHalf` 新增第三个输出 `inSwitchBand`：球在场内且 \|x\| ≤ `v1MidlineBand` 时为真。`ballHalfTrace` 相应新增 `switchBandSeconds`。这段时间已经计入蓝/红半场，只单独报告，不重复计算。

交接文档第 7 节的例子：球在 f = +0.10，蓝队仍处于 Defend 阶段。这时半场统计判为红半场（硬边界），分区判为 OppMiddle，协调器仍保持 Defend，因为 0.10 小于 0.15。三个结果各自符合设计，`inSwitchBand` 把这类时刻标记出来（`testDefendPhaseInsideBand`）。

### 3.2 规则（按顺序检查，先满足的先算）

| 顺序 | 分类（`tdp.halfCodes`） | 条件 | 是否计入半场时间 |
|---|---|---|---|
| 1 | Unknown (6) | 球坐标为 NaN 或 Inf | 否 |
| 2 | Stoppage (0) | 比赛暂停：`t < pauseUntil` | 否，单独统计 |
| 3 | Goal (5) | 整球越过门线 \|x\| > 4.57，且在门柱内（与裁判配置相同） | 否 |
| 4 | OutOfPlay (4) | 整球越过门线（门柱外），或整球越过边线 \|y\| > 3.07 | 否 |
| 5 | Midline (3) | x 恰好等于 0（若设置了 `P.y3MidlineBand`，则为 \|x\| ≤ 该值） | 单独统计 |
| 6 | BlueHalf (1) | x < 0 | 是 |
| 7 | RedHalf (2) | x > 0 | 是 |

`ballHalfTrace` 的时间约定不变：
- 采样保持，每行代表 [t, t + dt)。
- 暂停时间不分给任何半场。
- 进球数用比分列（62–63 列）统计。
- 跨半场只统计 Blue ↔ Red 的切换。

### 3.3 与 Qin 的规则逐行对照（V1.2 比赛记录）

之前只是**从代码上**比较了两套规则，结论是"基本一致"。这次用 `yuQinHalfReconcile` 在**同一份比赛记录**上逐行分类：Yu 用 `ballHalfTrace`，Qin 用 `qinBehaviourMetrics`（H1 规则）。两套结果都映射到 Qin 的六个标签，再逐行比较。工具先核对自己复算的 Qin 结果与 `qinBehaviourMetrics` 完全相同（误差 < 1e-9 s），然后才输出对照结果。

| V1.2 比赛（300 s，蓝 vs 红） | 左半场 | 中线 | 右半场 | 暂停 | 重开转换拍 | 出界 | 不一致的行 |
|---|---|---|---|---|---|---|---|
| Neutral vs Neutral | 208.00 | 15.45 | 69.55 | 6.80 | 0.20 | 0 | **0** |
| Aggressive vs Defensive | 94.15 | 7.75 | 196.10 | 1.95 | 0.05 | 0 | **0** |
| Defensive vs Aggressive | 172.70 | 7.75 | 117.55 | 1.95 | 0.05 | 0 | **0** |

表中的秒数 Yu 和 Qin 完全相同。Task 2（B-Y4）又在 30 场 V1.2 比赛、共 9000 s 上复核了一次，结果也逐秒一致。

对照中确认的几点：
- **中线：** Qin 的容差 1e-9 和 Yu 的"恰好 x = 0"没有区别。中线秒数全部来自开球前球停在 (0, 0) 等待的时间，不是比赛中压线。
- **暂停：** Yu 的"暂停"等于 Qin 的"暂停 + 重开转换拍"。重开转换拍是进球或出界后、裁判写入重置的那一拍，每次重置 1 拍（0.05 s）。两套规则对这一拍都不计入半场时间，只是标签不同。
- **出界、进球：** 记录里球一出界，同一拍就被裁判重置，所以这两类在真实记录里都是 0 s。两者的判据（整球越线）已经用可控轨迹验证一致（`testYuAndQinHalfRulesAgreeOnControlledTrace`）。

**结论：两套规则在 V1.2 记录上逐行一致，半场统计可以任选其一，结果相同。** 正式口径仍需 Qin 确认签字。

## 5. 默认站位核查（F4 第 5 节）

`spatialStationTable(tdp.v12Config())` 的计算条件：球在正前方中线上，横向位置取球在全场宽度内的所有情况。Neutral / Aggressive / Defensive 的 `defenderDist`、`screenDepth`、`counterDepth` 和是否补位**直接读取 `tdp.v12PolicyParams`**。读出的数值与之前从交接文档抄录的完全相同（Neutral 1.8 / 1.4 / 0.4，Aggressive 2.6 / 0.8 / 0.4，Defensive 1.5 / 2.0 / 1.0），所以下表与 V1.1 版的结论一致。"离线"指站位点到最近一条区域纵深线的距离；小于 0.20 m 时，站位点所属的区域编号可能来回跳变。

| 策略 | GK | DF（门→球连线） | MF 防守 | ST 防守 |
|---|---|---|---|---|
| V1 / V1.2 Neutral | −4.15，1 号区，离线 0.35 | −2.70，2 号区，离线 0.20 | −1.40，4 号区，**离线 0.10** | −0.40，4 号区，离线 0.40 |
| V1.2 Aggressive | 同上 | −1.90，**3 号区**（球在两侧时为 2 号区），离线 0.40 | −0.80，4 号区，离线 0.70 | −0.40，4 号区，离线 0.40 |
| V1.2 Defensive | 同上 | −3.00，2 号区（球在两侧时可进入 1 号区），离线 0.50 | −2.00，3 号区，离线 0.50 | −1.00，4 号区，离线 0.50 |

**DF 已知异常（6.3），用 5 cm 网格统计：** 球在本方半场时，V1.2 的 DF 公式（与 V1 相同：`block = ownGoal + defenderDist × threat / distance`）有两类问题：DF 点比球更远离本方球门（站到球前面），以及 DF 与球重叠（中心距小于 robotR + ballR = 0.22 m）。V1.1 版只统计了第一类。

| defenderDist | 1.8（Neutral） | 2.6（Aggressive） | 1.5（Defensive） |
|---|---|---|---|
| 原公式：DF 站到球前面 | 16.9 % | 36.9 % | 11.4 % |
| 原公式：DF 与球重叠 | 8.9 % | 13.0 % | 7.2 % |
| `tdp.goalSideBlock`：站到球前面 | 0 % | 0 % | 0 % |
| `tdp.goalSideBlock`：与球重叠 | 0 % | 0 % | 0 % |
| 其中启用门线规则的球位 | 1.3 % | 1.0 % | 1.6 % |

修正方法：
- **一般情况：** 沿球门到球的连线取距离 `min(defDist, |球 − 球门| − gap)`，gap = robotR + ballR + 0.05 = 0.27 m。球远时结果与原公式完全相同。
- **球贴近门线（Y4，新增）：** 球后面已经没有站一个机器人的空间（上面的点会比 f = −L/2 + robotR 更深）。这时 DF 站在门线上 f = −4.35，位于球靠球门中心的一侧：横向 `lat = s × min(defDist, |lat_ball| − gap)`，s 为球的横向符号（球在正中时取 +1）。`goalSideBlock` 的第三个输出 `onLine` 标记这种情况。该规则与一般情况连续：球很靠边时，结果与原公式相差不到 1 mm。
- V1.1 版把"球离门线不足 0.20 m"这一窄带直接排除在统计之外，现在这一带也有明确规则，并已计入上表。

**MF 的两个移动站位（交接第 5 节第 4、5 行）。** 这两个站位随球或 ST 移动，所以不是取一个点，而是扫描所有可能位置：MF 补位用与上面相同的本方半场 5 cm 网格球位，MF 进攻让 ST 走遍整个对方半场。由 `[T, D, M] = spatialStationTable()` 的第三个输出 `M` 给出。

| 站位 | 适用策略 | 示例位置（f） | 扫描到的区域 | 离线 < 0.20 m 的比例 | 其他检查 |
|---|---|---|---|---|---|
| MF 补位：球与本方球门的中点，离球门不超过 `v12DefenderDist` | Neutral（1.8） | 球在中线正前方时 −2.70，2 号区，离线 0.20 | 只在 1–2 号区 | 23 % | 100 % 位于球和本方球门之间；1.3 % 的球位下离球不足 0.30 m（球紧贴门前时） |
| 同上 | Defensive（1.5） | −3.00，2 号区，离线 0.50 | 只在 1–2 号区 | 30 % | 同上 |
| MF 进攻：ST 身后 0.70 m、侧方 0.80 m | V1 与 V1.2 全部策略 | ST 在 f = +2.0 时为 +1.30，5 号区，离线 0.20 | 4–8 号区 | 38 % | 13 % 的情况落在本方半场（ST 在 f < 0.70 时） |

结论：
- **MF 补位**始终在本方罚球区内，且总在球的门侧，符合"补位"的预期。Neutral 下，球在远处时补位点正好就是 DF 的阻挡点（同为 1.8 m），DF 出去拦截时 MF 接替原位，衔接合理。补位点只在 1.3 % 的球位下离球太近（不足两个机器人半径），都发生在球紧贴门线时，这时 GK 和上抢者已在附近，可以接受。
- **MF 进攻**在 ST 刚过中线时会落到本方 4 号区。这是"跟在 ST 身后"的自然结果，不是错误，但说明 MF 进攻站位不能用"必须在对方半场"来验收。
- 两个站位离区域线较近的比例都在 23–38 %，**战术代码不应根据 MF 自身所在的区域编号做决策**，否则编号会在线附近来回跳变；区域判断应只用于球的位置（已带 0.20 m 滞回）。
- Aggressive 不使用补位（`v12PolicyParams('aggressive').cover = false`），V1 也没有补位规则，所以表中没有这两行。
